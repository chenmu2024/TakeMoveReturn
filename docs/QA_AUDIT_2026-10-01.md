## Confirmed findings, ordered by impact

### 1. Maintenance decimal cost is rejected (P1)

`src/app/app/maintenance/page.tsx:76` uses an over-escaped HTML pattern. Testing the actual attribute pattern with the JavaScript `v` regular-expression flag rejects `0.00` and `12.50`, but accepts `0` and `1250`. The default value is `0.00`, so native validation can block Record service. Correct the literal decimal matcher and verify both browser validation and existing server-side amount checks.

### 2. Damage and maintenance silently stop at fixed limits (P1)

Damage loads only 500 tools and 100 reports. Maintenance loads only 500 tools, 100 schedules and 50 events. Neither page provides pagination or a larger-history control. A Pro workspace can have 2,000 tools, so valid tools beyond the selector limit cannot be chosen here. Tool names for historical entries can also fall back to “Tool record”. Add paginated history and company-scoped tool search; fetch names for the displayed history IDs independently of the selector.

### 3. Privacy request fulfilment remains operationally incomplete (P1)

The application inserts requests and displays their status. The tracked request schema gives authenticated users read/insert permission only; no application processing/fulfilment route or operator review screen was found. This does not prove no manual process exists outside the repository. Document and implement a review/verification/status/audit workflow before claiming deletion, rectification or restriction is completed by the website. Do not silently erase custody history or other members' data.

### 4. Import history contradicts current progress (P2)

`src/components/import-preview.tsx:56` refreshes `job` but not `recentJobs`. The just-completed browser run visibly showed 3/3 completed alongside 0/3 queued. Merge each polled result into the matching history row so clicking the history entry does not restore an obsolete state.

### 5. Tools overview omits holder and location (P2)

The current Tools table has Tool, Asset code, Status and Updated columns. Its introductory copy promises “See who holds each tool”, but the overview cannot answer who or where without opening details. Add company-scoped holder/location display with clear “Unassigned” values, preserving pagination and avoiding per-row requests.

### 6. Setup and count copy ignores existing records (P3)

The dashboard action is statically “Add first tool” even when tools exist (`src/app/app/[...slug]/page.tsx:9`). The observed Tools pagination says “1 records”, and setup says “1 tools added”. Use existing counts to choose action wording and singular/plural labels.
